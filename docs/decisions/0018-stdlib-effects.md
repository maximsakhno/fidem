# 0018. Эффекты стандартной библиотеки

- Статус: реализовано
- Дата: 2026-11-28
- PR: #33
- Связано: 0001 (начальный концепт); README → «Эффекты стандартной библиотеки»

## Контекст

Разбор того, чего не хватает для минимального веб-приложения, показал: первой же команде «создать» нужны ID новой сущности и текущее время. Контракт детерминизма запрещает обработчику вызывать часы и генераторы случайных значений напрямую, а готовых эффектов для этого не было. Каждое приложение писало бы одни и те же эффекты заново.

## Цель и границы

- Входят: эффекты текущего времени, случайного UUID и случайных значений с обработчиками на стандартной библиотеке.
- Не входят:
  - пауза (`asyncio.sleep`) — для неё нет примера из приложения;
  - UUID версии 7 — он есть в стандартной библиотеке только с Python 3.14, а проект поддерживает 3.13;
  - прежние значения при ретрае операции — это отдельная фича.

## Решение

- **Эффекты живут вне ядра.** Это обычные эффекты с обработчиками, ядро для них не меняется.
- **Все эффекты внутренние**, поэтому их yield-ят и гарды, и запросы. Например, гард может проверить, не истёк ли токен.
- **Случайные значения криптостойкие.** Поэтому коды подтверждения и токены безопасны по умолчанию, а для бизнес-логики такой генератор не медленнее обычного.
- **Модуль с реэкспортом из корня пакета.** Extras модулю не нужны, поэтому импорт такой же, как у остального публичного API (0014).

## Развилки

### Откуда брать UUID

- Выбрано: случайный UUID версии 4.
- Почему: согласованность при ретрае — задача общего механизма на ID операций и эффектов, а не отдельного эффекта.
- Отвергнуто: UUID, выведенный из ID эффекта. Ретрай получал бы тот же UUID без журнала, но UUID можно вычислить заранее по ID сообщения, а оно может прийти от клиента.

### Как подключать обработчики

- Выбрано: приложение явно передаёт список объявлений в Environment.
- Почему: при автоматической регистрации ядру понадобилось бы правило, как подменить обработчик в тесте, а сейчас повторное объявление эффекта — ошибка.
- Отвергнуто: Environment регистрирует обработчики сам.

## Нюансы

- **Ретрай операции получает новые значения.** Эффекты повторяются с теми же ID, но время, UUID и случайные значения при повторе другие. Если запись прошла в первой попытке, во второй идемпотентный обработчик её пропустит: в БД останется UUID первой попытки, а обработчик сообщения продолжит работу с UUID второй.
- **В тесте окружения один эффект не подменить добавлением своего объявления**, потому что повторное объявление — ошибка. Нужное объявление придётся отфильтровать из списка.

## Сочетание с другими фичами

- **Тесты генераторов** подставляют значения эффектов напрямую, обработчики им не нужны.
- **Durable-режим** запишет значения эффектов в журнал, и восстановленная операция получит прежние.

## Открытое

- Возвращать при ретрае прежние значения по ID эффектов — вместе с общим механизмом ретраев на ID операций и эффектов.
- Пауза — когда появится пример из приложения; UUID версии 7 — при переходе на Python 3.14.
- Подмена одного эффекта в тесте окружения — когда появится реальный тест, которому это нужно.
