# 0020. Ядро в отдельном пакете

- Статус: реализовано
- Дата: 2026-11-28
- PR: #35
- Связано: 0014 (публичный API пакета), 0009 (запросы и транзакции как эффекты); README → «Архитектура», «Сообщения»

## Контекст

Следующая большая фича — пользовательский API: объявления на декораторах, класс `Fidem`, автодискавери. Он строится поверх строгого внутреннего API (`StagedCommandDef`, `EffectDef`, `EnvironmentImpl`) и сводится к нему. По 0014 весь публичный API импортировался из корня `fidem`. Если положить туда и пользовательский API, рядом окажутся `@command_handler` и `StagedCommandDef`, и пользователь не поймёт, что из этого брать.

## Цель и границы

- Входит: где лежит внутренний API, что импортируется из корня, имя у объявления запроса.
- Не входит: сам пользовательский API, версия у команд.

## Решение

- **Корень `fidem` отдан API приложения:** сообщения, категории эффектов, типы генераторов, транзакции, `Proceed`, контексты, эффекты stdlib, настройки диспетчера, `Error` и ошибки, которые ловят во время работы. Пользовательский API добавится туда же.
- **Внутренний API — в `fidem.core`.** Его корень реэкспортирует всё, что раньше давал корень `fidem`, включая ошибки объявлений: их не ловят, а видят в traceback при старте.
- **Ядро физически лежит в пакете `fidem/core/`** и ничего не импортирует из `fidem` вне него. Границу проверяет тест по импортам модулей ядра.
- **Корень драйвера тоже даёт только API приложения.** Внутреннее, например хранилище диспетчера asyncpg, импортируется из модуля драйвера.
- **У объявления запроса нет имени.** Запросы не сериализуются, а повтор объявления ловится по типу. Общий базовый класс объявлений сообщений убран: у команд имя есть, у запросов нет.

## Развилки

### Где лежит внутренний API

- Выбрано: отдельный пакет `fidem.core`, корень `fidem` — для приложения. Это пересмотр 0014, где весь публичный API жил в корне.
- Почему: пользователь сразу видит, что ему брать, а внутренний API остаётся доступным для авторов драйверов и для редких случаев, которые пользовательский API не покрывает.
- Цена: все импорты внутреннего API поменялись.
- Отвергнуто: пользовательский API в `fidem.app`, корень как есть — ничего не ломается, но удобный API пришлось бы искать, а в корне осталось бы API для разработчиков фреймворка.

### Пакет или реэкспорт

- Выбрано: модули ядра перенесены в `fidem/core/`.
- Почему: граница видна по путям и проверяется автоматически.
- Отвергнуто: `fidem.core` как реэкспорт модулей, которые остались на месте, — граница была бы только на словах.

### Как проверять границу

- Выбрано: тест разбирает модули ядра и ищет импорты `fidem` вне `fidem.core`.
- Почему: запрет ruff на модуль (`banned-api`) действует на все подмодули, поэтому `fidem` нельзя запретить, не запретив `fidem.core`. Инструмент вроде import-linter — лишняя зависимость ради одного правила.

## Нюансы

- Имена в SQL совпадают с путями модулей: таблица `fidem.outbox` и секция миграций `fidem.outbox` — это имена в БД, они не переехали вместе с модулем `fidem.core.outbox`.

## Сочетание с другими фичами

- Новое имя внутреннего API добавляется в корень `fidem.core`, имя для приложения — ещё и в корень `fidem`.
- Новая ошибка объявлений остаётся в `fidem.core`, ошибка времени работы попадает и в корень `fidem`.
- Пользовательский API живёт вне `fidem/core/` и сводится к объявлениям ядра.
