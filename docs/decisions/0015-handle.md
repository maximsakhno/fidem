# 0015. Один вход для команд и запросов

- Статус: реализовано
- Дата: 2026-11-27
- PR: #30
- Связано: 0011 (таблица outbox), 0013 (запись событий в outbox); README → «Сообщения», «События», «Архитектура»

## Контекст

У Environment и движка было два входа: `execute` для команд и `query` для запросов. Они различались только именем: команда и запрос выполняются одним путём, а различаются объявлением и набором допустимых эффектов.

## Цель и границы

- Входит: один метод выполнения команды и запроса.
- Не входит: выполнение обработчиков событий — это работа диспетчера outbox.

## Решение

- **Команду и запрос выполняет один метод `handle`.** Тип результата берётся из сообщения, поэтому обе проходят через одну сигнатуру без потери типа. Необъявленная команда или запрос — одна ошибка `MessageNotDefinedError`.
- **Событие снаружи не выполняется и не публикуется.** Его публикует обработчик команды, а обработчики события выполняет диспетчер: одна строка outbox — доставка события одному обработчику.

## Развилки

### Запускать ли обработчики событий через `handle`

- Выбрано: нет, `handle` принимает только команду и запрос.
- Почему: событию нужен был бы параметр с именем обработчика, лишний для команды и запроса. Это признак, что запуск обработчика события — другая операция, чем выполнение сообщения: её делает диспетчер по строке outbox.
- Отвергнуто:
  - `handle(event, handler=...)` выполняет один названный обработчик — параметр нужен только событиям;
  - `handle(event)` выполняет все обработчики по очереди — непонятно, что делать, если упал второй из трёх, и обработчики событий в обход outbox теряют свои статусы и ретраи.

### Публикация события снаружи

- Выбрано: публичного `publish` нет, событие появляется только из обработчика команды.
- Почему: события — внутренний механизм приложения. Проверка прав гардами для них не нужна, а мидлвари есть у каждого обработчика события свои.
- Отложено: `publish(event)` для записи события в outbox снаружи — до реального примера, которому он нужен.

### Ошибки поиска обработчика

- Выбрано: одна `MessageNotDefinedError` вместо `CommandNotDefinedError` и `QueryNotDefinedError`.
- Почему: команда и запрос ищутся по одному ключу — типу сообщения.

### Переходный период для `execute` и `query`

- Выбрано: удалить сразу.
- Почему: пакет ещё не опубликован, устаревшие обёртки некому поддерживать.

## Сочетание с другими фичами

- Диспетчер outbox получит внутренний способ выполнить обработчик события по строке: `id` строки уже равен `message_id` операции обработчика (0011).
