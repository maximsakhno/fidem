# 0019. Входы гардов

- Статус: реализовано
- Дата: 2026-11-28
- PR: #34
- Связано: 0003 (DI для обработчиков сообщений), 0005 (гарды вместо DI сообщений); README → «Входы гардов»

## Контекст

Разбор того, чего не хватает для минимального веб-приложения, показал: гарду неоткуда взять токен, кроме самого сообщения. Гард получает только сообщение, его контекст и значения других гардов, поэтому токен приходилось класть полем в каждую команду. Транспорт протекал в доменные сообщения, а с журналом durable-режима токены попали бы в БД вместе с командами.

Решение 0005 оставило аутентификацию внутри fidem: вызывающий код не проверяет токен сам. Значит, ему нужен способ передать сырые данные вызова отдельно от сообщения.

## Цель и границы

- Входят: передача данных вызова в `handle` рядом с сообщением, их объявление и проверки при создании движка и при вызове.
- Не входят:
  - входы для обработчиков эффектов, например чтобы пробросить токен пользователя во внешний сервис, — до реального примера;
  - входы вложенных команд и запросов — вместе с ними;
  - необязательный вход через `X | None` — до реального примера.

## Решение

- **Вход — встроенная зависимость операции**, как контекст сообщения, только значение даёт вызывающий код. Отдельного скоупа нет: вход живёт ровно одну операцию.
- **Входы получают только гарды.** Мидлвари и обработчик получают результат гарда, например пользователя, а не токен (0005). Если обработчику нужно сырое значение, его отдаёт тривиальный гард, и решение сохранить значение в журнал становится явным.
- **Вход объявляется в общем списке с гардами**, а не в зависимостях Environment. Гарды резолвит движок по своему графу, а граф гардов и граф эффектов разделены (0003).
- **Вход сопоставляется по типу через `isinstance`**, поэтому тип входа — отдельный класс приложения. Голые строки токена и локали не различить.
- **`handle` проверяет входы до первого гарда.** Вход необъявленного типа и неоднозначный вход — ошибки. Вход, который нужен гардам операции, но не передан, — тоже ошибка. Объявленный вход, который операции не нужен, игнорируется.
- **Входы не видны дальше гардов.** Их нет ни в контексте сообщения, ни в вызове эффекта, поэтому их не видят мидлвари эффектов, обработчики эффектов и сериализация.
- **Обработчики событий входов не получают.** Их выполняет диспетчер, и передать входы ему некому.

## Развилки

### Кто получает входы

- Выбрано: только гарды.
- Почему: журнал durable-режима сохраняет аргументы обработчика. Если обработчик берёт токен напрямую, токен попадёт в БД, а при восстановлении окажется просроченным. В журнал вместо токена попадают значения гардов.
- Отвергнуто: гарды, мидлвари и обработчики сообщений.

### Где объявлять

- Выбрано: в общем списке с гардами.
- Почему: граф гардов уже принимает провайдеры двух видов — гарды и встроенные зависимости, а вход — третий вид в том же графе. По месту объявления видно, что вход получают только гарды.
- Отвергнуто:
  - в зависимостях Environment — это граф эффектов, и объявление пришлось бы передавать в движок, ломая разделение графов;
  - отдельным списком в движке — лишний параметр, который всё равно попадает в тот же граф.

### Название

- Выбрано: «вход гарда» (`GuardInputDef`).
- Почему: название говорит, кто получает значение, и читается рядом с объявлениями гардов.
- Отвергнуто:
  - «параметр» — в DI так уже называется параметр функции;
  - «метаданные вызова» — их обычно понимают как словарь «ключ — значение», а входы сопоставляются по типу;
  - «значение вызова» — не говорит, кто получает значение.

### Объявленный вход, который операции не нужен

- Выбрано: игнорировать.
- Почему: веб-слой обычно одним общим кодом передаёт токен в каждый запрос и не знает, какой команде он нужен. Строгая проверка заставила бы его повторять требования каждой операции.
- Отвергнуто: ошибка для любого входа, который операции не нужен.

### Как передавать входы в `handle`

- Выбрано: позиционными аргументами после сообщения, а ID сообщения — только по имени.
- Почему: вызов читается как «сообщение и его входы».
- Цена: ломает API. Тайпчекер не ловит старый вызов с позиционным ID сообщения, такой вызов падает только во время работы. Пакет не опубликован, поэтому переходный период не нужен.
- Отвергнуто: входы отдельным именованным аргументом — ничего не ломает, но вызов длиннее.

### Необязательный вход

- Выбрано: отсутствие выражает значение входа, например токен без строки, и решает гард.
- Почему: поддержка `X | None` в DI — новое правило, а примера, которому оно нужно, нет. Публичным командам токен не нужен, и его отсутствие ошибкой не будет.
- Отложено: `X | None`.

## Нюансы

- **Ограничение «только гарды» держится на графе.** Сначала мидлвари и обработчик связывались через тот же граф, что и гарды, и могли получить вход параметром. Теперь граф даёт каждому потребителю свой набор встроенных зависимостей: гардам — со входами, мидлварям и обработчику — без. Обработчик события, гардам которого нужен вход, падает при создании движка как зависимость, которая не найдена, без отдельной ошибки.
- **Гард мог молча перекрыть вход.** Гард с именем, который возвращает тип входа, выбирался по имени параметра вместо входа вызывающего кода. Поэтому значение гарда не может совпадать с типом входа или быть связанным с ним наследованием, даже у гарда с именем.
- **Не каждый класс годится в тип входа.** Protocol без проверки во время выполнения и `Any` — тоже классы, но `isinstance` с ними падает. Такие типы отвергаются при объявлении, а не на первом вызове.
- **`str` как тип входа допустим, но опасен:** входом станет любая строка, в том числе ID сообщения, по ошибке переданный позиционно.

## Сочетание с другими фичами

- **Durable-режим** запишет в журнал значения гардов, а не входы, поэтому токены не попадут в БД.
- **Ретрай мидлварью сообщения** гарды не перезапускает, поэтому входы повторно не нужны.
- **Вложенные команды и запросы** не наследуют значения гардов. Откуда они берут входы, надо решить вместе с ними.

## Открытое

- Входы для обработчиков эффектов — когда появится пример с пробросом токена во внешний сервис.
- Входы вложенных команд и запросов — вместе с ними.
- `X | None` для необязательного входа — когда появится пример.
