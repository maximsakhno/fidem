# 0007. Мидлвари сообщений

- Статус: реализовано
- Дата: 2026-11-23
- PR: #11
- Связано: 0004 (мидлвари эффектов), 0005 (гарды); README → «Мидлвари сообщений», «Режимы выполнения»

## Контекст

По концепту мидлвари сообщений — чистые effectful-функции. Нужна сквозная логика вокруг обработчика команды: кеш, ретраи, логирование попыток. При этом мидлварь не должна нарушать гарантии обработчика, например атомарность, а мидлвари не хотелось делить на отдельные виды для staged и atomic. И хотя durable ещё не реализован, концепция не должна рассыпаться, когда до него дойдёт дело: мидлвари могут писать, а операцию надо уметь восстановить с середины.

## Цель и границы

- Мидлвари для всех команд: проверка объявлений — и для staged, и для atomic, выполнение — для staged.
- Концепт durable-режима, в котором работают мидлвари и гарды.
- Не входят: выполнение atomic, реализация durable, версии мидлварей, встроенная ретрай-мидлварь, запросы и события.

## Решение

- **Мидлварь** — генераторная функция, как обработчик: свободная сигнатура (сообщение, его контекст, значения гардов), yield-ит эффекты и возвращает результат операции.
- **Внутреннюю часть цепочки мидлварь запускает управляющим эффектом «продолжить»** (`Proceed`). Он выполняет следующую мидлварь, а после последней — обработчик, и возвращает результат. Эффекты внутренней части мидлварь не видит и подменить не может, подменить можно только результат. Аргументов у него нет: подменить сообщение нельзя.
- **Порядок:** гарды обработчика и всех его мидлварей → мидлвари, первая в списке — внешняя → обработчик.
- **Мидлварь yield-ит любые эффекты, в том числе запись,** кроме сообщений и чужих управляющих эффектов.
- **Мидлварь может не продолжать** (кеш) **или продолжать несколько раз** (ретрай). Каждый раз внутренняя часть запускается заново, и её эффекты получают те же ID, поэтому повторные записи идемпотентны. Гарды не перезапускаются.
- **Ошибка внутренней части приходит в мидлварь** в точке «продолжить», её можно поймать. Ошибки фреймворка в мидлварь не попадают.
- **У мидлвари стабильное имя,** от него зависят ID её эффектов: у каждой мидлвари свой поток ID, поэтому добавление мидлвари не сдвигает ID обработчика и других мидлварей. Регистрация — как у мидлварей эффектов: общий список и замена для отдельной команды.
- **Ретраи после ошибки — мидлварью.** За движком остаётся только восстановление после падения процесса в durable-режиме: мидлварь его не сделает, потому что падает вместе с процессом.
- **Концепт durable:**
  - один журнал на операцию, у каждой записи указан источник: гард, мидлварь или обработчик;
  - при восстановлении вся цепочка, включая гарды, проигрывается заново на сохранённых результатах, поэтому значения гардов сериализовать не нужно;
  - «продолжить» — тоже шаг журнала, у каждой попытки внутренней части свой раздел;
  - журнал копится в памяти и сбрасывается в БД перед первой записью из любого источника: до первой записи операцию можно безопасно выполнить с нуля;
  - в журнале сохраняется состав цепочки с именами и версиями мидлварей, чтобы восстановление шло тем же кодом.

## Развилки

### Как мидлварь вызывает внутреннюю часть

- Выбрано: управляющий эффект «продолжить», который возвращает только результат.
- Почему: мидлварь не может подмешать эффекты в обработчик и нарушить, например, атомарность.
- Отвергнуто: доступ мидлвари к генератору обработчика и его эффектам.

### Одна попытка или сколько угодно

- Выбрано: продолжать можно сколько угодно раз.
- Почему: ядро минималистично — ретраи и логирование попыток реализуются мидлварью, а не движком.
- Отвергнуто: не больше одного вызова и ретраи в движке.

### Один вид мидлварей для staged и atomic

- Выбрано: один вид.
- Почему: для мидлвари «продолжить» — один шаг, а её собственные эффекты — отдельные шаги вне транзакции. Иначе одни и те же мидлвари пришлось бы писать дважды.

### Запись в мидлвари

- Выбрано: разрешена.
- Почему: кешу нужно сохранить результат после промаха.

### Журнал durable-режима

- Выбрано: один журнал на всю цепочку с источником у каждой записи и проигрывание всей цепочки при восстановлении.
- Почему: это единый механизм для гардов, мидлварей и обработчика вместо отдельного для каждой части.
- Отвергнуто:
  - сохранять только прогресс обработчика, а мидлвари не журналировать — их записи терялись бы при восстановлении;
  - сохранять аргументы обработчика вместо проигрывания гардов — значения гардов пришлось бы сериализовать.

### Имя мидлвари

- Выбрано: обязательное стабильное имя.
- Почему: на нём строятся ID эффектов и журнал. Имя типа не подходит: у мидлварей, созданных одной фабрикой с разными настройками, оно одинаковое.

## Нюансы

- Повторное продолжение после успеха тоже разрешено, его последствия — на совести мидлвари.
- Потоки ID мидлварей и гардов строятся так, чтобы не совпасть ни при каких именах.
- Ошибку фреймворка движок отличает по месту возникновения, а не по типу. Иначе такая же ошибка, пришедшая от обработчика эффекта, тоже не попала бы в обработчик сообщения.

## Сочетание с другими фичами

- Atomic: «продолжить» выполняет обе фазы и возвращает результат транзакции.
- Вложенные сообщения: пока мидлварь не может их yield-ить.
- Версии мидлварей появятся вместе с версиями сообщений.
