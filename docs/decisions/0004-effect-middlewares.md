# 0004. Мидлвари эффектов

- Статус: реализовано
- Дата: 2026-11-23
- PR: #8
- Пересмотрено: 0014 (ретрай эффекта БД мидлварью эффекта идёт в той же транзакции, неявной или явной, а не в новой)
- Связано: 0002 (DI для обработчиков эффектов), 0003 (DI для обработчиков сообщений); README → «Мидлвари эффектов»

## Контекст

По концепту сквозная логика вокруг эффектов — ретраи, логирование, метрики, кеширование — реализуется вне ядра мидлварями, а мидлвари эффектов — обычные функции. Кроме того, фабрики зависимостей сообщений со временем жизни приложения могли yield-ить эффекты на старте, когда сообщения ещё нет: у таких эффектов не было ни сообщения, ни детерминированных ID.

## Цель и границы

- Мидлвари для обработчиков эффектов: форма, место относительно DI, настройка, обработка ошибок.
- Попутно: убрать эффекты на старте, чтобы у каждого эффекта было сообщение.
- Не входят: мидлвари сообщений, доступ мидлварей к зависимостям из DI.

## Решение

- **Мидлварь** — функция, которая получает описание вызова (сообщение, эффект и их контексты) и функцию «вызвать дальше» без аргументов. Описание вызова мидлварь только читает.
- **Мидлвари работают до DI.** Последний вызов «дальше» создаёт зависимости эффекта, вызывает обработчик и закрывает зависимости.
- **Мидлварь может не вызвать «дальше»** (кеш, заглушка) или вызвать несколько раз (ретрай), в том числе одновременно.
- **Настройка:** общий список задаётся в Environment, у отдельного эффекта свой список заменяет общий, пустой список — без мидлварей. Первая в списке — внешняя. Список для каждого типа эффекта готовится один раз при создании Environment.
- **Ошибка мидлвари — ошибка эффекта:** она попадает в обработчик сообщения.
- **Через мидлвари проходят все эффекты,** в том числе эффекты фабрик зависимостей сообщений.
- **Зависимости мидлварь получает только через замыкание.**
- **Эффектов на старте нет.** Фабрики зависимостей сообщений со временем жизни приложения — только готовые объекты и простые функции. Yield-ить эффекты могут только фабрики со временем жизни сообщения. Это время жизни стало значением по умолчанию: аутентификация и проверка прав — самый частый случай.
- **Контекст сообщения создаётся в одном месте — в Environment.** Движок получает его готовым и передаёт сообщение и контекст в каждую инструкцию вызова эффекта.

## Развилки

### Мидлвари до DI или после

- Выбрано: до DI.
- Почему:
  - ретрай получает новые ресурсы: новое соединение, новую транзакцию, а ошибка коммита при закрытии тоже попадает в ретрай;
  - кеш и заглушки прерывают вызов, не тратя ресурсы;
  - логи и метрики видят полную стоимость вызова и ошибки создания зависимостей;
  - контракт мидлвари не зависит от DI.
- Цена: мидлварь не получает зависимости из DI, а зависимости со временем жизни сообщения при ретрае не пересоздаются.
- Отвергнуто: после DI — ретрай повторял бы вызов с той же оборванной транзакцией, а кеш платил бы за создание зависимостей.

### Форма мидлвари: декоратор или функция с «вызвать дальше»

- Выбрано: функция, которая получает описание вызова и «вызвать дальше».
- Почему: данные передаются явно, мидлварь тестируется простым вызовом. Окружение запускает цепочку там, где ему известны зависимости текущего сообщения, и передаёт их напрямую.
- Отвергнуто: декоратор, который принимает обработчик и возвращает новый. Цепочка собиралась бы один раз, и данные текущего вызова пришлось бы передавать через неявное глобальное состояние.

### Подмена эффекта в мидлвари

- Выбрано: запрещена, мидлварь только читает описание вызова.
- Почему: подменять эффект — плохая идея, а работала бы подмена лишь частично: сообщение и его контекст общие для всех эффектов сообщения.

### Как упаковать данные для мидлвари

- Выбрано: один неизменяемый объект — описание вызова.
- Почему: DI и контексты не меняются, а новые поля добавляются, не ломая существующие мидлвари.
- Отвергнуто: класть сообщение и эффект в их контексты — сообщение дублировалось бы, а DI пришлось бы сопоставлять параметризованные контексты. Иерархия контекстов (контекст эффекта ссылается на контекст сообщения) — возможно, позже, вместе с ID корреляции и причины.

### Эффекты фабрик приложения

- Выбрано: запрещены. Пересматривает решение из 0003.
- Почему: на старте нет сообщения. ID эффектов не вывести из ID сообщения, а мидлварям и обработчикам эффектов нечего передать как сообщение.

### Где создаётся контекст сообщения

- Выбрано: в Environment.
- Почему: Environment нужен контекст ещё до первого эффекта, для зависимостей эффектов со временем жизни сообщения. А движок остаётся чистым: генерация случайного ID сообщения уходит из него.
- Отвергнуто: создавать в движке — Environment получал бы контекст только с первой инструкцией.

## Нюансы

- При одновременных вызовах «дальше» зависимость со временем жизни сообщения создаётся один раз, второй вызов ждёт первый. Иначе создались бы две копии, и одна не закрылась бы.
- Вызов «дальше» после завершения сообщения — ошибка, а созданная при этом зависимость сразу закрывается.

## Сочетание с другими фичами

- Мидлвари сообщений: по концепту — чистые effectful-функции.
- Вложенные команды: их контексты будет создавать движок от родительского, и Environment придётся брать зависимости каждой операции из инструкции.
- ID корреляции и причины: удобный момент ввести иерархию контекстов.
